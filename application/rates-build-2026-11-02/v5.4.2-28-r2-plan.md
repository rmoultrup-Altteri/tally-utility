## Blocking

### B1. The tier-rate CHECK cannot be restored from a dump (Opus B1; executed, confirmed by the author)
PostgreSQL 16 prints `(@ * 10000).floor()` back as `@ * 10000.floor()`, which does not parse ("trailing junk after numeric literal"). `pg_dump` puts the CHECK inside `CREATE TABLE rate_item_versions`, so a restore loses the table and everything built on it (Opus: 33 errors, 136 tables of 137). `pg_upgrade` goes through the same dump (predicted).
**Fix:** `@ * 10000 % 1 != 0`, which prints back as `(@ * 10000) % 1 != 0` and reparses (author executed). Re-anchor mutation N10.
- Test: a battery check that the stored definition of every -28 CHECK reparses: `pg_get_constraintdef` fed back through a scratch `CREATE TABLE` in the battery's transaction. Add a dump-and-restore of a clone to the verification for this patch.
- Lesson for `sql/PATCH-LESSONS.md`: a jsonpath in a CHECK must survive its own deparse.

[a schema object must survive dump and restore]

### B2. A dependency can be closed with no reason (Codex B1; executed)
`closed_reason ~ '[[:alnum:]]'` is NULL for a NULL reason, and a CHECK accepts NULL. -21 required a reason.
**Fix:** `closed_reason IS NOT NULL AND closed_reason ~ '[[:alnum:]]'` in the closing branch.
- Test: an omitted reason, a NULL, a blank and a punctuation-only reason, for both a retraction and a supersession.
- Add a mutation.

[PATCH-LESSONS blank-checks-whitelist-alnum: coalesce the NULL leg; -21 K1]

### B3. A consolidated parent with its own premise skips its children (Codex B3; Fable N4; Opus N2; executed)
`invoices_check` requires a premise or the consolidated flag, not that a consolidated parent has no premise. `invoice_time_zone_as_of` picks its branch from `location_id IS NOT NULL`, so a consolidated parent with a premise answers by that premise, and the mixed-zone children are never compared. A non-zero fee was admitted that way. A consolidated child with a premise likewise reads as a leaf, so "a nested parent is always refused" does not hold.
**Fix:** pick the branch from `is_consolidated`: a consolidated invoice reads its live children whether or not it has a premise of its own (if it has one, that premise's zone must agree with the children's too), and a child that is itself consolidated is refused, whatever its premise.
- Test: Codex's 02 B3 cases in the battery.

[Ryan 2026-11-02, option 1: a consolidated parent uses its children's premises, which must agree]

## Should fix

### S1. A long transaction can record a cycle in the past (Opus S1; executed with two committed sessions)
A row's `recorded_at` is its transaction's start, but the walk reads rows open at the moment of the insert. Session 1 begins; session 2 retracts B on A and commits; session 1 inserts A on B. The as-of read at an instant between the two returns {A>B, B>A}.
**Fix:** in the walk, `(d.recorded_until IS NULL OR d.recorded_until > NEW.recorded_at)` in place of `d.recorded_until IS NULL`. Rows this transaction closed carry `recorded_until = now() = NEW.recorded_at`, so they stay out and close-then-successor still works.
- Test: a race case beside `cycle-19.sh` (two committed sessions). Update L3's wording.
- Add a mutation.

[A-1: what was known at an instant is a DAG at every instant]

### S2. NaN passes the four-decimal checks (Fable S2; executed)
`'NaN' = round('NaN', 4)` is true for `numeric`. **Fix:** `rate_value <> 'NaN' AND rate_value = round(rate_value, 4)`; the same on `rate_override`. (Infinity is refused by `numeric(14,6)`; jsonb has no NaN.)
- Test and a mutation.

[K-06: a rate is a four-decimal number]

### S3. Tier shapes outside the documented one pass (Opus N6; Codex S2; Fable N1; executed)

**Fix:** state the scope in the CHECK's comment: the check covers `$.tiers[*].rate`, the documented shape (`rate_items.tier_config`'s comment); whether every tier carries a rate is the tier-shape check's (pre-existing `..._tier_config_required_for_tiered`), not this one. No widening of the check.
