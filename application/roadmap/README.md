# Go-live roadmap

The source of truth for the go-live plan and its dashboard: https://claude.ai/artifact/8aCPLAU3VnjiXL7ZW5mNNJ (private; share from the page's Share menu).

- `phases.json` (edit by hand): the phases, their status, parts, durations (low / likely / high weeks) and dependencies.
- `decisions.json` (edit by hand): the decision queue; set `status` to `answered` when a decision is made.
- `parity.json` (edit by hand): invariant counts by family; refresh after each parity re-measurement.
- `schedule.json`, `golive.json`, `phases-table.json`, `parts.json`: generated by `python3 tools/roadmap/schedule.py`. Do not edit them.

## Updating the dashboard (at session wrap-up)

1. Edit the hand-written files, then run `python3 tools/roadmap/schedule.py`. It prints the go-live date for each estimate.
2. Upload each changed file to the artifact as an asset (Artifact publish with `url`, `asset: true`, `file_path`).
3. Update that dataset's `source.url`, `source.name` and `updated` in the artifact store (`ArtifactData` update on `datasets/<id>`). Dataset ids: `phases` (phases-table.json), `schedule`, `golive`, `decisions`, `parity`, `parts`.

## How the estimate works

Each phase starts when the phases it depends on allow it to: `finish` waits for that phase to end, while `start` waits `lag_weeks` after it begins. Each phase then runs for its duration under the chosen estimate. The low estimate puts every phase at its low figure, and likewise for likely and high. Work that spans the year-end holidays is pushed out two weeks. The headline date is **ready to onboard** (the start of P10), meaning the product is built, tested and secured, so a first customer's onboarding can begin. That customer's go-live is the start of P12, shown separately. Each phase's `basis` says how its estimate was made. The estimate is only as good as the durations, so revise them as phases finish and real speed is known.
