## As built (r3, 2026-11-27)

Every item above is in the patch; its header lists them ("r3 (round 2's findings)"), and R6 and a new R8 carry the notes. Choices made in the build, by rule:

- **Item 1.** `collections_act_check` takes the instant an act is judged at (`p_at`): an execution passes its arrival, every other act passes NULL (as recorded now). A4 then reads "no successor recorded at or before the arrival", and A10 reads the decisions recorded by then. A10's query moved into `collections_cover_blocks()`, which item 5 reuses. Within one transaction every decision and the arrival carry the same instant, so a successor written in the same transaction still supersedes (battery S1b).
- **Item 2.** The location's row is read `FOR SHARE` after the order's, so a transfer waits for an execution in flight (race CR11), and an execution waits for a transfer in flight and then sees it (CR11b).
- **Item 3.** The line check takes the charge's advisory lock (two lines billing one charge are ordered); "once" means on a bill that is not void, so a corrected bill may bill the charge again after the first bill is voided.
- **Item 4.** `a_enforce_late_fee_ledger` reads the row's own type first, so `tally_void`'s `void_reversal` rows and every other type return before another table is read (`triggers-run-as-every-writer`). A posting is allowed while no other posting of the charge stands (one undone by a reversal no longer counts). `battery-22`'s January late fee now posts a gated charge (a bill, a decision and the charge, none of which adds a ledger row), so `battery-22` needs -26, as `battery-21` does.
- **Item 5.** An execution locks its order's subject (act `disconnect_order`) before the execute decision's; the lock-order rule says so.
- **Item 7.** From `payment_plan` any escalation step moves the bill; from `resolved` or `written_off` only a gated one (a reminder is the only ungated escalation step). Battery E2b4 now expects a reminder to leave a resolved bill where it is.
- **Item 8.** The stamp follows -19's rule: a superuser's value is kept (history loads), so the battery's owner fixtures can test each bound alone (S8c, S8d).
- **Item 9.** The race script prints FAIL only with damage, else BROKEN; the mutation runner's classifier is a function with a ten-case self-test on literal outputs, run before every mutation run.
- **Item 10.** The trigger list records each trigger's enabled mode, so `dunning_events`' earlier add-only triggers are pinned as they are. Policies and column grants are compared as exact sets; the generator skips the invariant call while it bootstraps (empty lists would fail the exact sets).
- **Note (draft bills).** A dunning step on a bill not issued, or void, is refused [E2c].
- **Changed in the build: the draft-bill note.** A step on a draft bill was first refused too; the full `ci.sh` run showed `battery-19` logs a reminder on a draft bill (its log-stamping test). Since the note was low ("the core chooses the bills") and the gated steps already need an issued bill (C3b), r3 refuses a step on a **void** bill only [E2c], and R7 names an ungated step on a draft bill as the core's.
