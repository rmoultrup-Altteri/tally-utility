### Should-fix

- **S1. The template-trigger invariant checks name and ENABLE ALWAYS only, so a same-named trigger pointing at another function, or at another timing, passes it.** `rule_table_trigger_errors` (1490–1510) excludes `rule_row_insert` / `rule_row_history` from the sorts-after clause **by name** and, for a registered table, requires only `tgname = n AND tgenabled = 'A'`. Reproduced on `fable617`: (a) `CREATE OR REPLACE TRIGGER rule_row_insert BEFORE INSERT … EXECUTE FUNCTION zz_sneak()` on a registered table — the assertion passes (A5) and an insert is no longer validated (only the table's own `terms NOT NULL` stopped mine); (b) `CREATE OR REPLACE TRIGGER rule_row_history BEFORE DELETE …` (UPDATE dropped) — the assertion passes and `UPDATE … SET source_note = 'edited freely'` on a law row **succeeds** (A5b, stored); (c) `rule_row_insert` re-made as an AFTER trigger — passes (A5c); (d) on the fixture's own `zz_fee_rules`, `rule_row_history` re-pointed at a no-op `zz_other_hist()` with the same timing — passes, `pg_trigger` shows `rule_row_history=zz_other_hist:27` (J1). This is the owner-DDL class of r5 S2, and the fix was adopted so that CI "catches a later migration"; a migration that writes `CREATE OR REPLACE TRIGGER` under the template's name — the natural way to "adjust" a trigger — is exactly what it does not catch. Fix: for a registered table require, per template trigger, `tgfoid = 'public.enforce_rule_row_insert()'::regprocedure` (resp. `enforce_rule_row_history`, `enforce_rule_registry_no_truncate`) and `tgtype = 7 / 27 / 34` (BEFORE ROW INSERT; BEFORE ROW UPDATE OR DELETE; BEFORE STATEMENT TRUNCATE — the values the fixture's registration produces), and make the sorts-after exclusion by identity, not name, so a foreign function under a template name is flagged there too. Battery: a replaced function and a narrowed timing, each refused by the assertion (and at registration, where a pre-existing same-named trigger currently fails with 42710, which is fine); mutations dropping the `tgfoid` and `tgtype` clauses.
- **S2. A pre-convention row that has not been filled is the law: lookups return it, citations accept it, and a tariff is "measured" against it.** On an adopting table registered with an unfilled legacy row (`terms IS NULL`): `rule_law_row_as_of` returns its id (H1); `rule_law_row_cite` and `rule_row_cite` accept it (H2, H3); a tariff table registered against that law table accepts a `tally_app` tariff row under it (H5b) — the comparator sees `terms -> 'governs'` NULL and finds nothing looser, and coverage counts the row as law. Nothing in the machinery forces the fill to complete: R14 is a sequence the migration follows, and r6's own blank-key check (1854) now makes a legacy row with a blank key **unfillable** — the fill is refused (C1: 22023), the row stays with no document, can still be closed, and remains a law row for lookups by any other key it shares. A legacy row whose stored spans disagree with its sets is likewise fillable only after a repair the migration must notice (H4, A3e). "Unknown law is not permission" (2269, 2100) should hold for a row whose terms are unknown. Fix, two halves: (i) `rule_law_row_as_of`, `rule_row_cite` and the tariff check's law read refuse — by name, "row … is not yet adopted into the convention" — a row with `terms IS NULL` (skipping it in `as_of` would also work: the lookup then says no law, which is the truth; refusing is louder); (ii) adopting registration runs `rule_key_check` over every existing row's key and compares each row's stored spans with its sets, so every row it registers **can** be filled, as it already refuses rows whose template CHECKs fail (C2: a lower-case state is refused by the added constraint). Battery: a lookup, a citation and a tariff row against an unfilled row, each refused; an adopting registration refused for a blank legacy key; mutations for each.
- **S3. A `strategy` property may be optional.** The version rule (538–550) fires on any object with a `strategy` property and requires `version` in `required`; it never requires `strategy` itself. A tariff schema with `properties.strategy = {type: string, const: flat}` and `required: ["version"]` registers (F5), and `{"fee": {"version": 1}}` then validates with no errors (probe 3) — a strategy object with no strategy name, which the core cannot resolve (`law/README.md:67`: "a decision point names a strategy and its version"). Fix: in the same clause, `required` must contain `strategy`. Battery R4y; a mutation dropping the clause.
